### 1.3 部署脚本 `contracts/script/**` —— 门禁 1/2/3 已落地并编译通过

**`DeployMainnet.s.sol`**

- `AssetConf` 新增 `desc` 字段，`_preflight` **校验 `feed.description()`**（值取自 `scripts/feed-health-check/feeds.ts`：`ETH / USD`、`USDC / USD`、`USDT / USD`、`DAI / USD`、`cbBTC / USD`）→ 拦住"feed 地址张冠李戴"。
- ⭐ **显式 `oracle.setMaxStaleness(feedMaxAgeCfg)`**，默认 **26 小时**（`MAINNET_FEED_MAX_STALENESS` 可覆盖）—— **这是解除 H2 的关键一行**。
- ⭐ **显式 `oracle.setMaxDeviation(...)`**，默认 **20%**（`MAINNET_MAX_DEVIATION` 可覆盖）。原来脚本完全没设，走合约默认的 **30%**，等于 30% 的偏离都不告警。
- ⭐ **用 `updatePrice()` 初始化偏差基准**，并断言 `lastValidPrice(ETH) > 0`。原实现下 `lastValidPrice` 恒为 0 → `maxDeviation` 永不触发。
- 预检的新鲜度阈值改用与运行时**同一个配置**（原来预检 26h / 运行时 1h，两边不一致正是 H2 的成因）。
- `_verifyTiers` 扩展为**校验所有已注册抵押品**的 5 档（原来只验 ETH；cbBTC 漏配会静默不可借）。
- 新增**所有已注册资产 `getAssetPrice > 0`** 的部署后断言（否则运行时 `_priceOf` revert）。
- 预检增加 `roundId > 0 && updatedAt > 0`（round 完整性）。
- `cap = 0` 时打印 `[warn] ... UNLIMITED` —— 让"机制建好但没接线"在部署日志里可见。

**`MainnetDeployAndTransfer.s.sol`**

- 删除 `_envAddrOr` / `_envStrOr`（`try/catch` 静默回落）→ 改用 `vm.envOr`，变量格式非法时**直接 revert**，不再悄悄用默认值。
- 新增硬断言：`safe / treasury / pauser / governance != deployer`（原来一个都没有）。
- 传入 Timelock 时先校验 `minDelay > 0` 且 `safe` 持有 `DEFAULT_ADMIN / PROPOSER / EXECUTOR`。
- ⭐ **新增 Step 8.5「撤销前移交确认」门禁**：在 `renounceRole` 之前用 12 条 `require` 确认接收方**已经真正拿到**全部角色与所有权并检查 `treasuryAddress`。这是原脚本最危险的空洞——只要前面有一笔 grant 失败或地址填错，Step 9 会把部署者撤成「协议无人可管理」且**不可逆**。
- Step 10/11 从 `console2.log` 改为 `require`（原来脚本"看起来成功"也可能实际没移交）。

**`contracts/.env.example`**：补充 `MAINNET_FEED_MAX_STALENESS`、`MAINNET_MAX_DEVIATION` 的说明（含 11–13h 实测依据）。

### 1.4 监控 `services/monitor/**`

- `AlertStore` 支持**重复提醒**（`ALERT_RENOTIFY_MINUTES`，默认 15 分钟）。原实现是纯边沿触发只推一次，运维漏看那一条 CRITICAL 后就再无提示。

### 3.3 非代码层面（但决定你能否承受一次事故）

- **用上限把最大损失锁死**：`maxStaleness` 修好≠没有别的未知 bug。软启动期把单市场限到 $5 万、TVL ≤ $10–20 万，让任何未知问题的损失上限落在你能承受的范围内。
- **不要在软启动期做激励活动**：激励会把 TVL 快速拉到未验证的额度上。
- **per-user 借款上限**：合约暂无（你文档 §6.1 已自述）。软启动期单一大额仓位是主要集中风险，只能在运营层控制（邀请制 / 人工过一遍大额仓位）——**必须有人真的盯着，写进流程**。
- **紧急操作手册**（建议今天就写）：
  - `LendingPool.pause()` = **不是全停**，只挡 `supply` / `supplyCollateral` / `borrow`；清算、还款、提现照常。
  - `ChainlinkOracle.pause()` = **真正的核按钮**，所有读价 revert → `borrow` / `withdrawCollateral` / `liquidate` / `handleBadDebt` / 部分 `repay` 一起停；但 supply 的 `withdraw` 与**全额** `repay` 仍可用（用户退出通道不被锁，这是好事）。
  - 确认 PAUSER 密钥在值班人手上。
