## 0. 先说本轮新增的一条 High（H2）

在整理修改方案、核对预言机参数时发现，**比 H1 更紧急**：

### H2. `maxStaleness = 3600` 与项目自己的 feed 心跳登记表（86400s）矛盾 → 平稳行情下全协议价格读取 revert

- 代码证据：
  - `contracts/src/oracle/ChainlinkOracle.sol:36` → `uint256 public maxStaleness = 3600;`
  - `contracts/src/oracle/ChainlinkOracle.sol:163` → `require(block.timestamp - updatedAt <= maxStaleness, "stale price");`
  - `scripts/feed-health-check/feeds.ts:15-19` → **5 个 Base feed 的 `heartbeatSec` 全部登记为 `86400`（24 小时）**
  - `contracts/script/DeployMainnet.s.sol:273-276` → 部署预检**容忍 feed 陈旧到 26 小时**，且脚本**从未调用 `setMaxStaleness`**
- 三处数字互相矛盾：预检容忍 26h、登记表声明 24h、运行时**只接受 1h**。

- 触发路径（无需攻击者）：
  1. Chainlink 是"偏差阈值 **或** 心跳，先到先触发"。USDC/USDT/DAI 这类稳定币的偏差阈值极窄且几乎不动 → 在平静时段**只能靠心跳更新，间隔可达 24 小时**。
  2. 一旦某个稳定币 feed 超过 1 小时没更新，`getAssetPrice(USDC)` 就 **revert**。
  3. `_priceOf`（`LendingPool.sol:950-954`）被 `_amountToWadUsd` 的上游 `_debtValueWad` / `_collateralValueWad` 调用 → 该市场**借款、还款、抵押取回、清算全部 revert**。
  4. 更糟：`_supplyCollateralCore`/`_borrowCore` 走的 `_oracleAnomalous()` 会遍历全部资产，**任一资产 stale 就锁死全池新增敞口**（即上一份报告的 M2）。

- 影响：这不是"理论风险"，而是**上线后按设计就会周期的可用性事故**，且窗口正好落在低波动时段——此时协议看起来"没人用"，但一旦有人要还款或清算也做不了。
- 为什么它比 H1 更急：H1 只影响前端读数（合约仍拒绝越界），**H2 直接让链上资金操作不可用，且清算通道也会一起失效**。
- **好消息：`maxStaleness` 是 `PARAM_ADMIN` 可改的存储变量，不需要重新部署合约即可缓解**（见批次 B6）。根治需要改成"逐 feed 陈旧阈值"（见批次 C）。

```ts
export function useAssetPrices(addresses: string[]): { prices: Record<string, number>; ready: boolean } {
  const { data } = useReadContracts({
    contracts: addresses.map((a) => ({
      address: PRICE_ORACLE as Address, abi: PriceOracleAbi, functionName: "getAssetPrice",
      args: [a as Address],
    })),
    query: { enabled: PRICE_ORACLE_READY, refetchInterval: 30_000, refetchIntervalInBackground: true, retry: false },
  });
  const d = data as unknown as Array<{ result?: bigint }> | undefined;
  const out: Record<string, number> = {};
  addresses.forEach((a, i) => {
    const raw = d?.[i]?.result;
    if (raw != null && raw > 0n) out[a] = Number(raw) / 1e8;

  const ready = PRICE_ORACLE_READY && addresses.every((a) => out[a] !== undefined);
  return { prices: out, ready };
}
```

```ts
import { parseUnits } from "viem";

/// 解析用户输入的十进制字符串为原始单位 bigint。返回 null 表示输入非法。
export function parseAmount(input: string, decimals = 6): bigint | null {
  const s = input.trim();
  if (!s) return null;
  try {
    const v = parseUnits(s, decimals);
    return v > 0n ? v : null;
  } catch {
    return null;   // 非法字符 / 小数位超限
  }
}
```

```ts
/// 按 collateral.address × tier 拉取链上 LTV / LT，避免前端硬编码表与治理改参脱节。
export function useCollateralRisk() {
  const contracts = COLLATERALS.flatMap((c) =>
    Array.from({ length: 5 }, (_, k) => k + 1).flatMap((tier) => [
      { address: ADDRESSES.riskManager as Address, abi: RiskManagerViewAbi,
        functionName: "getMaxLTV" as const, args: [c.address as Address, BigInt(tier)] },
      { address: ADDRESSES.riskManager as Address, abi: RiskManagerViewAbi,
        functionName: "getLiquidationThreshold" as const, args: [c.address as Address, BigInt(tier)] },
    ]),
  );
  const { data } = useReadContracts({ contracts, query: { refetchInterval: 60_000 } });
  const ltv: Record<string, number[]> = {};
  const lt: Record<string, number[]> = {};
  COLLATERALS.forEach((c, ci) => {
    ltv[c.symbol] = []; lt[c.symbol] = [];
    for (let k = 0; k < 5; k++) {
      const a = (data as Array<{ result?: bigint }> | undefined)?.[ci * 10 + k * 2]?.result;
      const b = (data as Array<{ result?: bigint }> | undefined)?.[ci * 10 + k * 2 + 1]?.result;
      ltv[c.symbol].push(a != null ? Number(a) / 1e16 : 0);
      lt[c.symbol].push(b != null ? Number(b) / 1e16 : 0);
    }
  });
  return { ltv, lt };
}
```

`BorrowTab` / `PositionPanel` / `StressTestPage` 用 `useCollateralRisk()` 的结果替换 `COLLATERAL_TIER_LTV` / `COLLATERAL_TIER_LT` / `TIERS[].ltv/lt`；**读不到时禁用借款**（与 A1 同样的 fail-closed 原则）。`config.ts` 里的硬编码表保留为**仅用于首屏骨架预览**，并在注释中标注"不得作为计算依据"。

### C3. 修 M4 —— 让物理储备也能溢出到 Treasury

**设计**：不用给 ReserveManager 增加资金外流接口（避免新攻击面），而是让池子把物理储备**拉回池内**，再通过既有的 `treasuryAccrued`/`collectTreasury` 通道付给 treasury。账务天然守恒（储备原本已在池外，拉回后 `cash` 与 `treasuryAccrued` 同增同减）。

`contracts/src/ReserveManager.sol` 新增（接口 `IReserveManager` 同步声明）：

```solidity
/// @notice 仅借贷池可把物理储备拉回自己（用于储备溢出划转 / 坏账覆盖）。
///         `to` 强制等于 lendingPool，杜绝把储备转到任意地址。
function withdraw(address token, address to, uint256 amount) external {
    require(msg.sender == lendingPool, "not pool");
    require(to == lendingPool, "to != pool");
    require(amount > 0, "amount=0");
    IERC20(token).safeTransfer(to, amount);
}
```

`contracts/src/LendingPool.sol` 替换 `_overflowReserveToTreasury`（`:825-838`）：

```solidity
function _overflowReserveToTreasury(uint8 marketId) internal {
    Market storage m = _market(marketId);
    uint256 totalBorrows = _totalBorrowsToken(marketId);
    if (totalBorrows == 0) return;
    uint256 reserveTarget = totalBorrows * reserveTargetRatio / WAD;
    uint256 physicalReserve = IERC20(address(m.asset)).balanceOf(address(reserveManager));
    uint256 reserveAssets = m.totalReserve + physicalReserve;
    if (reserveAssets <= reserveTarget) return;
    uint256 overflow = reserveAssets - reserveTarget;

    // 1) 先动账面储备（仍在池现金内）——只改记账，代币留在池里等 collectTreasury
    uint256 fromBook = overflow > m.totalReserve ? m.totalReserve : overflow;
    if (fromBook > 0) {
        m.totalReserve -= fromBook;
        m.treasuryAccrued += fromBook;
        emit ReserveOverflowTransferred(fromBook);
    }

    // 2) 再把超出部分的"物理储备"拉回池内并计为 treasury 应付款
    uint256 remaining = overflow - fromBook;
    if (remaining > 0 && physicalReserve > 0) {
        uint256 fromPhysical = remaining > physicalReserve ? physicalReserve : remaining;
        reserveManager.withdraw(address(m.asset), address(this), fromPhysical);
        m.cash += fromPhysical;
        m.treasuryAccrued += fromPhysical;
        emit ReserveOverflowTransferred(fromPhysical);
    }
}
```

- `LendingPool.sol` 顶部 `IReserveManager` 接口加 `withdraw(address,address,uint256)`。
- `accrue()` 加 `nonReentrant`（`:170-172`），因为 `_accrueMarket` 现在可能触发代币转账。

`getAssetPrice` 在 **fallback 模式**下额外要求 `!priceAnomalous[asset]`，避免"缓存价 + 陈旧标记"同时放松。

部署脚本相应改成逐资产指定：ETH/USD 用 `2 hours`（偏差阈值紧、更新频繁），USDC/USDT/DAI 用 `26 hours`（偏差窄、靠心跳），cbBTC 用 `2 hours`。

## 批次 D：运维监控

### D1. 修 M8-a —— 解决"只监控硬编码用户名单"

现状：`services/monitor/config/positions.json` 的 `users` 是 **空数组**（已核验），即当前监控**什么都没盯**。

分两层解决：

**短期（无合约改动，1 天内可做）**：把监控从"名单驱动"改成"名单驱动 + 从池快照反推候选集"。协议虽然没有事件，但 `metrics.jsonl` 会持续累积；同时增加一个**手动登记 + 校验**的入口——运维把已知借款人填进 `positions.json`，并在每次交互前后从链上 `userBorrowNorm(user, marketId)` 复核该地址是否真在名单里。至少不要让 `users: []` 静默通过：

```ts
// index.ts 启动时
if (cfg.users.length === 0) {
  console.error("positions.json 的 users 为空——监控将不会发现任何可清算仓位，请先填入关注地址");
  process.exit(1);
}
```

**根治（需配合合约一起做，建议与批次 C 同批）**：在 `LendingPool` 重新引入**最小事件集**（现在为 EIP-170 全删了），只留 3 个、字段最省：

```solidity
event Supplied(address indexed user, uint8 indexed marketId, uint256 amount);   // supply / supplyCollateral 共用
event Borrowed(address indexed user, uint8 indexed marketId, uint256 amount);
event Liquidated(address indexed liquidator, address indexed target, uint8 indexed marketId, uint256 debtCovered, uint256 collateralSeized);
```

然后用 Subgraph（或 `viem` 的 `getLogs` + 本地 sqlite）按地址去重构建监控集合，替换硬编码名单。**这一步是"及时清算→控制坏账"闭环的前提**，不做的话监控的价值很有限。

### D2. 修 M8-b —— 告警重复推送

`services/monitor/src/alerts.ts`

```ts
export class AlertStore {
  private prev = new Map<string, boolean>();
  private lastSent = new Map<string, number>();

  constructor(
    private out: (a: Alert) => void,
    /// 未恢复的告警每隔多久重推一次（默认 15 分钟）。0 = 关闭重推（退回旧行为）。
    private reNotifyMs = 15 * 60_000,
  ) {}

  set(key: string, level: Alert["level"], active: boolean, message: string): void {
    const was = this.prev.get(key) ?? false;
    const last = this.lastSent.get(key) ?? 0;
    const now = Date.now();
    if (active && (!was || (this.reNotifyMs > 0 && now - last >= this.reNotifyMs))) {
      this.out({ level, key, message, at: new Date().toISOString() });
      this.lastSent.set(key, now);
    }
    if (!active) this.lastSent.delete(key);
    this.prev.set(key, active);
  }
}
```

`index.ts` 里 `new AlertStore(cb, Number(envOr("ALERT_RENOTIFY_MINUTES", "15")) * 60_000)`；CRITICAL 建议单独用更短的间隔（如 5 分钟）。
