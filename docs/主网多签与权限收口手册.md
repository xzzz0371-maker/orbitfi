# ZZZ Lend — 主网多签与权限收口手册（Base · chainId 8453）

> 版本：v1.0 · 2026-09-03 ｜ 状态：Safe 合约地址已在 Base 主网核验有代码；真网执行需你准备真实多签 owner 与 gas。

---

## 1. 目标

把部署者的中心化权限收口到 **Safe 多签 +（可选）Timelock**：
- 协议参数（LTV/LT、closeFactor、bonus、利率、储备比例、市场/抵押品新增、cap）→ 必须经 Timelock 延迟（默认 24–48h，建议 48h）。
- pause/unpause → 由独立 PAUSER（也放 Safe）**即时**执行，不经过 Timelock（应急熔断不能有延迟）。
- Treasury 地址、多签 owner 按上线前治理值设置。
- 部署者撤销 DEFAULT_ADMIN/PARAM_ADMIN/PAUSER/Owner 后**不再能调用任何管理函数**。

## 3. Timelock 配置

- 部署模板：`DeployMainnet.s.sol` 已支持 `MAINNET_TIMELOCK_MIN_DELAY`。
  - 设 `MAINNET_TIMELOCK_MIN_DELAY=172800`（48h，建议）。
  - 由脚本部署 OZ `TimelockController(minDelay, proposers=[SAFE], executors=[SAFE], admin=SAFE)`（admin 建议=Safe 或 0 自管）。
- 角色：proposer=Safe；executor=Safe；admin=Safe（自管时 admin=0，由 timelock 自己 schedule 自己的角色变更）。
- **走 Timelock**：LTV/LT 档位、closeFactor/bonus、maxBorrowTier、利率 preset/参数、reserveTarget/factor、treasuryFactor、市场新增、抵押品新增、supply/collateral cap、treasuryAddress 变更。
  → 这些函数调用方持 PARAM_ADMIN 或 Ownable owner。收口后该角色**只授给 timelock 合约**，任何变更必须先 `schedule` 再等延迟后 `execute`。
- **不走 Timelock（即时）**：`pause/unpause` —— PAUSER 角色授给 **Safe**（多签一签即触发？不，Safe 是 2/3，需多人确认但无 timelock 延迟；可接受的熔断粒度）。
  - 更严格可在 Safe 内再设"快速门槛"：把 PAUSER 授给 Safe，但要真正即时需 owner 快速 2/3 签名（数分钟内）。协议已可用。

## 4. 权限收口完整流程（对照 `script/MainnetDeployAndTransfer.s.sol`）

| Step | 动作 | 说明 |
|---|---|---|
| 1 | 部署全套主网参数合约 | 复用 DeployMainnet（真实 feed/token，cbBTC/ETH 抵押，wstETH 关） |
| 2 | 确定 Safe 地址 | 若提前创建，以 env `MAINNET_ADMIN=<SAFE>` 传入；否则脚本用工厂部署 |
| 3 | 部署 TimelockController | 若 `MAINNET_TIMELOCK_MIN_DELAY>0`（推荐 48h） |
| 4 | treasuryAddress = Safe（或独立 treasury 多签） | 池参数 |
| 5 | PAUSER → Safe | 独立熔断（不经 timelock） |
| 6 | pool/oracle/riskEngine 的 DEFAULT_ADMIN_ROLE → timelock | 角色管理员 |
| 7 | pool/oracle 的 PARAM_ADMIN_ROLE → timelock | 参数变更延迟执行 |
| 8 | IRM/RiskManager/ReserveManager `transferOwnership(timelock)` | Ownable 走 timelock |
| 9 | 部署者 renounceRole（逐个）| DEFAULT_ADMIN / PARAM_ADMIN / PAUSER / Ownable 已移交 |
| 10 | 验证：部署者调任何管理函数 → revert | |
| 11 | 验证：Safe(经 timelock) 可改参数；Safe(PAUSER) 可即时 pause | |

> 顺序关键：先授角色/owner 给 timelock/Safe，**最后**才撤销部署者。renounceRole 只能由本人（部署者）调用。

## 5. 验证清单（真网执行后逐项打勾）

- [ ] 部署者 `hasRole(DEFAULT_ADMIN_ROLE, deployer)==false`（pool/oracle/riskEngine）
- [ ] 部署者 `owner()==timelock`（IRM/RiskManager/ReserveManager）
- [ ] `timelock.hasRole(PROPOSER_ROLE, SAFE)`、`EXECUTOR_ROLE` ok
- [ ] `pool.PAUSER_ROLE` 授给 SAFE；`pool.paused()==false`
- [ ] 部署者直接 `pool.setReserveFactor(...)` → revert（AccessControl）
- [ ] SAFE 经 `timelock.schedule(pool.setReserveFactor)` → warp delay → `execute` 生效
- [ ] SAFE 直接 `pool.pause()` 生效（即时熔断）
- [ ] treasuryAddress == Safe/treasury，collectTreasury 可提取
- [ ] ETH/cbBTC 抵押档位非 0；USDC/USDT/DAI 市场供应 cap 已设
- [ ] fork dress rehearsal 全绿（`forge test --match-contract ForkMainnet`，已于 09-03 通过 8/8）

## 6. 回滚方案

- 合约**不可升级**（无 proxy，K4 决策）：一旦部署错误 = 整组重新部署到新地址 + 旧池归档。回滚粒度为"整池"。
- 上线前零/极低 TVL 期若发现严重问题 → 优先 `pause()`（PAUSER，即时）冻结新增，然后评估重部署。
- **旧池资产处理**：若回滚时已有存款/借款，需治理决定迁移路径（新池空启动 + 公告 + 引导取回旧池）。无内置迁移器。
- **紧急暂停流程**：1) owner 快速 2/3 签名调 Safe → `pool.pause()`（PAUSER）；2) 评估是否 `enableFallback`/`pause` oracle；3) 公告；4) 视情况启动回滚或修复后再 `unpause`。
- 备份：`deployments/mainnet.json` 归档；广播记录保留；Safe owner 私钥离线冷存。
