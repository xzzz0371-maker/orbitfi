## 1. 高危发现

### F6（High，设计/治理）：管理员中心化 = 单一故障点 + 潜在 rug 面
- **位置**：所有合约构造器把 DEFAULT_ADMIN / PARAM_ADMIN / PAUSER 全部授予部署者；`InterestRateModel`/`RiskManager`/`ReserveManager` 为 Ownable（owner=部署者）。
- **风险面**：
  - `LendingPool.setPriceOracle / setInterestRateModel / setRiskManager / setLiquidationManager / setReserveManager`：PARAM_ADMIN **可换任意模块地址**，换成恶意合约即可：`setReserveManager(恶意)` 令坏账资金转走；`setLiquidationManager(恶意)` 令清算没收量异常；`setPriceOracle(恶意)` 注入任意价格 → **实质 rug 能力**。
  - `SwitchableOracle`（PAUSER 可 `enableSettable`）+ `setPrice`（PARAM_ADMIN 可设**任意价**）：若测试后忘记 `disableSettable()`，池子永久运行在管理员设定价上（E2E 用的就是这个通道）。
  - `RiskManager.setTier` 可把 maxLTV 提到 90%、`setCloseFactor` 提到 100%：恶化风险参数。
  - `ChainlinkOracle.setFeed` 可换任意聚合器地址（无需真实 feed）。
- **结论**：非代码漏洞，但**生产上线前必须**：多签持有角色、部署者 `renounceRole`/移交、设置 `TESTNET_ADMIN` 并撤销部署者。测试网可接受（文档 §5/§6.6 已列）。
- **修复建议**：部署脚本移交三角色给多签并 `renounceRole(DEFAULT_ADMIN_ROLE, deployer)`；模块 setter 加 zero-address + 模块类型校验（或升级代理方案）。

### F11（High，设计/系统性风险）：存款人损失无上限 + 坏账缓冲薄弱
- **位置**：`handleBadDebt` 的 supplyIndex 削减公式 `newIndex = old × (supply - loss)/supply`，`loss ≥ supply` 时 index 直接归零（存款人 100% 归零）。
- **场景**：ETH 极端跌幅（如 -80%）→ 大量 tier5 仓位同时进入"抵押归零 + 残余债务"，储备（目标仅 `totalBorrows×3%`）瞬间耗尽，剩余损失全部传导给存款人，可能**一次事件抹掉大部分/全部存款**。
- **结论**：会计正确但**经济设计激进**；无单点代码漏洞。
- **修复建议**：提高储备目标 / 引入坏账分批摊销上限 / 对高 LTV 档位更早清算阈值；这是产品决策，需你审核。

## 2. 中危发现

### F1（Medium，已实证并修复）：`repay()` 全量还款取整下溢 → 小额仓位无法清债
- **位置**：`LendingPool.sol` `repay()` 与 `liquidate()`（修复前）。
- **根因**：`_getDebt6` 向上取整 `ceil(norm×index/WAD)`，而 `repay` 的 `normReduction = repayAmount×WAD/index`（向上取整）。当借款额很小（borrowNorm 与 1 个 USDC 微单位同量级）且计息后 `index > WAD` 时，`debt6` 进位到 `borrowNorm+1`，`normReduction` 也进位到 `borrowNorm+1` → `pos.borrowNorm -= normReduction` **下溢 revert**。
- **修复**：`repay`/`liquidate` 的 `normReduction` 增加 `if (normReduction > pos.borrowNorm) normReduction = pos.borrowNorm;`（与 handleBadDebt 一致）。回归测试见 `SecurityFixes.t.sol::test_F1_*`。
- **影响**：仅影响尘埃仓位（< ~0.02 USDC）；修复后不再 revert。

### F3（Medium，已修复）：`SwitchableOracle.setPrice` 无 `price>0` 与上界校验
- **位置**：`SwitchableOracle.setPrice`（修复前仅校验 `asset != 0`）。
- **修复**：`require(price > 0)` + `require(price >= 1e2 && price <= 1e14)`。回归测试 `test_F3_*`。

### F4（Medium，已修复）：模块 setter 缺零地址校验
- **位置**：`LendingPool` 5 个模块 setter（修复前无校验）。
- **修复**：全部加 `require(address(x) != address(0), "zero address")`；`setReserveManager` 额外校验 `code.length > 0`。回归测试 `test_F4_*`。

### F5（Medium，已修复）：fallback 冻结缓存价 + 偏差标记仅 `updatePrice` 更新（监控缺口）
- **位置**：`ChainlinkOracle` `useFallback` / `_getFallbackPrice` / `priceAnomalous`。
- **修复**：新增 `lastValidPrice` 稳定基准，`isPriceAnomalous` 改为实时内联计算偏差（不再依赖 updatePrice）；fallback 取舍文档化。回归测试 `test_F5_*`。

## 3. 低危发现

- **F2（Low，已修复）**：`handleBadDebt` 当 `getTotalSupply()==0` 时跳过 supplyIndex 削减，`lossToDepositors` 无处吸收 → 资金守恒被破坏。**修复**：级联吸收（存款人 → 账面 `totalReserve` → `treasuryAccrued`），由不变式保证损失必可完全吸收，守恒恒成立。回归测试 `test_F2_*`。
- **F7（Low，部署性）**：`MockUSDC.faucet` 无权限任意铸币。**仅限测试网**；若误上主网 = 无限增发灾难。主网部署用真实 USDC。
- **F8（Low，激励）**：深度水下仓位（抵押价值 ≪ 50% 债务）清算人会亏本 → 无人清算 → 坏账传导给存款人。属经济激励缺口。
- **F9（Low，已文档化）**：oracle `pause` 后 `getAssetPrice` revert → `liquidate` 也被阻断。取舍已文档化（宁可不清算，也不用错误价清算），回归测试 `test_F9_*` 固化当前行为。
- **F10（Low，会计）**：储备溢出只从**账面 `totalReserve`** 划转；物理储备超标部分不转 Treasury（安全设计）。

## 5. 审计中未覆盖但建议补充的检查项（自定义补充）

1. **同区块多次操作组合**：`supply→borrow→repay→withdraw` 在单一交易内的净效果（E2E 跨区块已验，未做同区块原子组合验证）。
2. **`withdrawCollateral` 在 oracle 异常/暂停时的行为**：有债时读价，oracle 故障则抵押品被锁（建议纳入 fallback 放行或紧急提款路径）。
3. **`supplyIndex=0` 后遗症**：一旦归零，`supply()` 除零 revert，池子对新增存款永久关闭；建议在上限兜底（如损失超过 95% 时触发系统级处理，而非静默归零）。
4. **换模块后的兼容性**：`setInterestRateModel` 换到不同接口实现的模型时，`getBorrowRatePerSecond` 语义差异可能导致异常利率。
5. **`test-out/` 覆盖数据**：覆盖率报告只针对三个核心合约 >90%，`InterestRateModel/RiskManager` 的边界未全部纳入压力矩阵。
6. **`getBorrowAPR` 用 `getUtilization()` 的瞬时值**：展示用，与 `_accrue` 内部同一时刻的 utilization 一致，无偏差。
7. **E2E 中 USDC feed stale 的兜底**：借/还/清算依赖 USDC 价，feed 长 stale 时功能全停；建议加入"价格停更超时后使用 fallback 缓存"或紧急暂停策略。
