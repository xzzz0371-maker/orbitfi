# OrbitFi 利率模型说明

来源：`contracts/src/InterestRateModel.sol`（借款利率）+ `contracts/src/LendingPool.sol`（存款利率与费率分配）
当前生效预设：**NORMAL** ｜ **2026-09-29 调整**（对标 Aave v3 Base）

---

## 一、先记住三个数字

| 项 | 值 | 含义 |
|---|---|---|
| `reserveFactor` | **4%** | 借款利息划入风险储备 |
| `treasuryFactor` | **2%** | 借款利息划入 Treasury |
| **存款人份额** | **94%** | 剩下的才是存款人的 |

**借款人付的利息，94% 给存款人，4% 进储备，2% 进 Treasury。**

另外 `reserveTargetRatio = 3%`：当某市场的储备超过该市场总借款的 3% 时，超出部分自动划转给 Treasury。

## 二、借款利率：三段曲线

| 段 | 利用率区间 | 起点 | 斜率 |
|---|---|---|---|
| 第一段 | 0 → **90.5%**（kink1） | 基础利率 **2.0%** | **3%** |
| 第二段 | 90.5% → **95%**（kink2） | 4.715% | **40%** |
| 第三段 | 95% 以上 | 6.515% | **150%** |

```
U ≤ 90.5%         借款APR = 2.0% + 3% × U
90.5% < U ≤ 95%   借款APR = 4.715% + 40% × (U − 90.5%)
U > 95%           借款APR = 6.515% + 150% × (U − 95%)
```

### 为什么是 90.5%

这个拐点直接对标 **Aave v3 的 `U_optimal`（90.5%）**。旧参数用 80%，导致 80% 之后利率过早飙升：

| 利用率 | 旧参数 T1 | 新参数 T1 |
|---|---|---|
| 90% | 7.45% | **4.70%** |
| 95% | 9.95% | 6.52% |

**旧参数下，90% 利用率时比 Aave 贵 62%，借款人会直接跑到 Aave。** 新曲线把"便宜区间"拉长到 90.5%，只在最后 10% 才陡增 —— 既留住借款人，又保住提现安全。

### 关键点（Tier 1）

| 利用率 | 旧 | **新** |
|---|---|---|
| 0% | 0.50% | **2.00%** |
| 50% | 2.50% | **3.50%** |
| 80% | 3.70% | **4.40%** |
| 85% | 4.95% | **4.55%** |
| **90%** | 7.45% | **4.70%** |
| **90.5%（kink1）** | — | **4.72%** |
| **95%（kink2）** | — | **6.52%** |
| 100% | 12.45% | **14.02%** |

## 三、档位溢价（Tier Premium）

| 档位 | LTV | 旧溢价 | **新溢价** |
|---|---|---|---|
| Tier 1 | 50% | +0% | **+0%** |
| Tier 2 | 60% | +1% | **+0.5%** |
| Tier 3 | 70% | +2% | **+1.0%** |
| Tier 4 | 75% | +3% | **+1.5%** |
| Tier 5 | 80% | +4.5% | **+2.5%** |

**为什么要降**：按新曲线，T5 @90% 若仍用 +4.5% 就是 9.2%，明显高于市场。降到 +2.5% 后是 **7.20%**，仍在 Aave 之上（Aave 无风险分层，统一 4.6%），但不再是"贵到没人借"。

> 溢价是**覆盖高风险档坏账成本**的唯一来源（储备只拿利息的 4%），所以不能压到 0。

## 四、存款利率

**存款 APY 由借款端推导，不是独立参数：**

```
存款APY = 加权平均借款利率 × 利用率 × 94%
```

"加权平均借款利率"是**链上按各档位实际借款额加权**算出来的，不是简单的 Tier 1 利率。

### 各利用率下的存款 APY（假设借款全在 Tier 1）

| 利用率 | 借款 APR | 存款 APY |
|---|---|---|
| 50% | 3.50% | 1.65% |
| 70% | 4.10% | 2.70% |
| **80%** | 4.40% | **3.31%** |
| 85% | 4.55% | 3.64% |
| **90%** | 4.70% | **3.98%** |
| 95% | 6.52% | 5.82% |
| 100% | 14.02% | 13.17% |

### 与市场的对比

| 协议 | 链 | 存款 APY | 借款 APR |
|---|---|---|---|
| **OrbitFi @90%** | **Base** | **3.98%** | **4.70%** |
| Aave v3 @~89.5% | Base | 3.80% | ~4.6% |
| Morpho | Base / ETH | 5.2–8.3% | 5.2–10.5% |

> **@90% 利用率下，OrbitFi 的存款和借款利率都略优于 Aave v3 Base。**
> Morpho 更高，但那是隔离市场 + 策展人策略，风险结构不同，不可直接比。
>
> 前端首页的 "Projected" 值用 **U=80% + Tier 1** = **3.31%**。
> 实际值随利用率和高档位借款占比变化 —— **链上数据永远优先于这个估算**。

## 五、另两个预设（应急用，当前未启用）

`marketGovernor`（默认 = admin 多签）可随时 `applyPreset` 切换：

| 预设 | 基础利率 | kink | 100% 利用率时 T1 |
|---|---|---|---|
| **NORMAL**（当前） | 2% | 90.5% / 95% | **14.02%** |
| HIGH_VOLATILITY | 2% | 65% | 67.5% |
| EXTREME | 5% | 50% | 175% |

后两个是**危机模式** —— 用极高利率抑制借款、逼还款。

> 切预设**不需要**走 Timelock（`marketGovernor` 可即时调用），这是刻意的 —— 危机响应要快。
> 代价是利率变更可以绕过 48 小时延时。

## 六、会影响你收益的几件事

1. **坏账会稀释存款人**：储备不够吸收损失时，`supplyIndex` 被下调，存款本金可能受损（设计如此，不是 bug）
2. **利用率高 ≠ 一定赚**：高利率往往伴随清算风险，坏账概率也高
3. **提现依赖池内现金**：利用率接近 100% 时池里没现金，提现要等借款人还款
4. **档位溢价不覆盖全部风险**：T5（80% LTV）的清算阈值是 90%，ETH 跌 10% 就触及清算 —— 这是高风险档位的固有属性，不是参数能消除的
